### 상세 내용

#### 배열 크기 48 → 50 확장
흙토람 엑셀 서식의 열 수를 48에서 50으로 확장하여 개인정보 동의 컬럼 2개를 추가.

| 위치 | 컬럼명 | 값 |
|------|--------|----|
| AW열 (index 48) | 개인정보 수집·이용 동의 | `Y` (자동) |
| AX열 (index 49) | 개인정보 제3자 제공동의 | `Y` (자동) |

영향 범위:
- `row1` ~ `row4` (헤더 행): `new Array(48)` → `new Array(50)`
- `dataRow` (데이터 행): `new Array(48)` → `new Array(50)`, `dataRow[48] = 'Y'`, `dataRow[49] = 'Y'` 추가
- 컬럼 너비 설정 (`colWidths`): AW, AX 각 `{ wch: 16 }` 추가
- 병합 셀 설정 (`merges`): AW3:AW4, AX3:AX4 병합 추가

## v1.7.74 — 그룹 삭제·수정 안정성 개선

### 변경 파일
- `src/soil/soil-script.js`

### 상세 내용

#### 1. 그룹 삭제 기능 (`deleteGroup` 메서드 신규)

같은 `groupId`를 가진 시료 묶음을 한 번에 삭제하는 메서드 추가.

```
동작 흐름:
1. groupId로 연관 시료 전부 조회
2. sampleLogs에서 일괄 제거 + saveLogs()
3. Firebase에서도 일괄 삭제
4. 수정 중이던 항목이 삭제 그룹이면 수정 모드 취소
5. 삭제된 접수번호를 입력란에 세팅 → 재입력 편의 제공
```

`deleteSample()` 메서드도 동일하게 개선:
- 시그니처에 `receptionNumber` 파라미터 추가
- 삭제 후 해당 기본번호가 더 이상 없으면 입력란에 자동 세팅

#### 2. 다작물 서브넘버 수정 버그 수정

**문제**: 작물이 여러 개인 필지 수정 시 서브넘버가 `321-1, 321-2, 321-3` 으로 생성되어 기본번호(`321`)가 사라지던 문제.

**원인**: `cropIndex + 1`로 계산하여 첫 번째 작물도 `-1`이 붙었음.

**수정**:
```js
// 수정 전
const receptionNumber = `${baseNum}-${cropIndex + 1}`;

// 수정 후 — 첫 작물은 기본번호, 두 번째부터 -1, -2
const receptionNumber = cropIndex === 0 ? baseNum : `${baseNum}-${cropIndex}`;
```

신규 접수 시(`addLog`)와 수정 시(`saveEditedGroup`) 양쪽 모두 적용.

#### 3. 수정 모드 필지 카드 재현 로직 개선

**문제**: 그룹 수정 진입 시 각 레코드의 `parcels[0]`을 단순 순회하여 다작물 서브넘버 레코드가 별도 필지로 표시되던 문제.

**수정**: `parcelIndex` 기준으로 레코드를 그룹화 후 같은 필지 내 작물(crops)을 병합하여 올바른 필지 카드 렌더링.

```
변경 전: groupLogs 순회 → parcels[0] 각각 카드 생성
변경 후: parcelIndex Map으로 그룹화 → 같은 parcelIndex의 crops 합산 → 카드 1개 생성
```

수정 진입 시 접수번호 입력란도 서브넘버 제거 후 기본번호만 표시:
```js
// 수정 전
this.receptionNumberInput.value = firstLog.receptionNumber;  // "321-1"

// 수정 후
const baseRecNum = (firstLog.receptionNumber || '').split('-')[0];
this.receptionNumberInput.value = baseRecNum;  // "321"
```

#### 4. Firebase 불필요 삭제 범위 수정

수정 시 기존 레코드 중 새 레코드에 ID가 재사용되지 않은 항목만 Firebase에서 삭제하도록 정확도 개선.

```js
// 수정 전 — 단순 slice, ID 재사용 여부 무시
const removedLogs = oldGroupLogs.slice(validParcels.length);

// 수정 후 — 새 ID Set과 비교
const newIds = new Set(newLogs.map(l => l.id));
const removedLogs = oldGroupLogs.filter(l => !newIds.has(l.id));
```

#### 5. 자동완성 겹침 수정 (`closeAllAutocomplete` 메서드 신규)

뷰 전환 시 열려있던 작물명/필지주소 자동완성 리스트가 닫히지 않고 다른 뷰 위에 겹치던 문제 수정.

```js
closeAllAutocomplete() {
    document.querySelectorAll('.crop-autocomplete-list.show, .lot-address-autocomplete-list.show')
        .forEach(el => el.classList.remove('show'));
}
```

`switchView()` 진입 시 항상 호출.

### 1. 흙토람 Tab 키 이동 개선

#### 변경 배경

기존 Tab 키는 `testDate`(검정일)부터 `usageCode`(용도구분)까지 전체 16개 필드를 순서대로 이동하고, 하위필지(`isSubLot=true`) 행도 일반 행과 동일하게 포커스 정지.

#### 신규 동작

| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| Tab 시작 열 | `testDate` (index 0) | `pH` (index 3) |
| Tab 종료 열 | `usageCode` (index 15) | `cec` (index 13) |
| cec에서 Tab | 다음 행의 `testDate`로 | 다음 행의 `pH`로 |
| `isSubLot=true` 행 | 포커스 정지 | 자동 건너뜀 |
| Shift+Tab | 역방향 전체 순회 | 역방향도 동일 규칙 적용 |

#### 구현: `moveFocusResult` 신규 메서드

Tab 전용 포커스 이동 함수. Enter 키는 기존 `moveFocus` 유지.

```
핵심 로직:
1. colIdx > END_COL(cec) → colIdx = START_COL(pH), rowIdx++
2. isSubLot 행 while 루프로 건너뜀 (무한루프 방지)
3. 숨김 컬럼(soiling, clay, NO3N, NH4N) while 루프로 건너뜀
4. 마지막 행 이후면 이동 안 함
```

무한루프 방지: 기존 재귀 방식 대신 while 루프 사용 (모든 남은 행이 isSubLot인 엣지케이스 대응).
