## 리뷰가 찾은 것 — 세 레인이 같은 곳을 가리켰다

### 🔴 `title` 속성 XSS — codex가 먼저, critic이 실행까지 확인

`escapeHtml`은 `window.escapeHTML`에 위임하는데 그 구현이 `div.textContent → innerHTML` 방식이라
**따옴표를 변환하지 않는다.** 실측:

```
escapeHTML('a"b<c')  →  a"b&lt;c        ← 따옴표 그대로
```

사유를 `title` 속성에 넣으면서 **속성 위치가 새로 생겼고**, 엑셀 값이 속성을 탈출했다.
직접 재현한 렌더 결과:

```html
<td class="is-conflict" title="기존값 5.3 → " ><img="" src="x" onerror="alert(1)>"">
```

critic은 `" onmouseover="window.__PWNED=1"` 페이로드로 **핸들러가 실제 실행됨**을 확인했다.
Electron은 CSP로 막히지만 **GitHub Pages 배포본에는 CSP meta가 없어** 그대로 실행됐을 경로다.

**왜 내 검증이 놓쳤나** — 내 XSS 테스트는 `<img src=x onerror=...>` 한 종류만 썼다.
그건 `escapeHTML`이 **처리하는** 문자(`<`,`>`)로만 이루어진 페이로드다. 변이 검증도
본문 경로만 확인했다. **페이로드 한 종류 = 검증 축 하나**였고, 속성 경로는 그 축에 평행했다.

더 나쁜 것은 수정 후 내가 처음 쓴 회귀 테스트도 **`img` 요소 수만 셌다**는 점이다.
실제 탈출은 태그를 만드는 대신 `td`에 속성을 주입했으므로 그 단언은 통과했다.
지금은 **요소의 속성 목록**을 직접 본다:

```
변이(escapeAttr → escapeHtml) 결과: ["&gt;&lt;img", "class", "onerror", "src", "title"]
```

조치: 속성 전용 `escapeAttr` 추가 + `escapeHtml`의 **window 위임을 걷어냈다**(다음 사람이
속성을 하나 더 추가해도 같은 함정을 밟지 않게).

### 🟠 sticky 헤더가 실제로는 붙지 않았다 — 두 레인이 독립적으로 실측

CSS 주석은 "헤더와 시료번호 열은 스크롤해도 남아야 한다"고 적어 뒀는데 **절반만 성립**했다.

`.importer-pv-scroll`의 `overflow-x:auto`가 CSS 규격상 `overflow-y`를 `visible` → `auto`로
승격시켜 **그 요소가 sticky의 기준 스크롤포트**가 된다. 그런데 높이 제한이 없어 스스로는
스크롤되지 않고, 실제로 움직이는 것은 바깥 `.importer-preview-list`(260px)다.

```
헤더 offset: 스크롤 전 1.0px → scrollTop=200 후 -199.0px   ← 밀려 사라짐
첫 열 offset(가로 400 스크롤): 1.0px                      ← 고정
```

**이건 이 티켓의 목적을 뒤집는다.** 옛 목록은 줄마다 항목명을 달고 있어 어디서든 자기설명적이었다.
새 표는 260px에 6행쯤 보이고, 7행부터는 헤더 없는 숫자 더미가 된다. 상한을 5→50으로 올린 것이
노출을 오히려 키운다.

조치: 두 축 스크롤을 안쪽 `.importer-pv-scroll`로 통합(바깥은 높이 제한 해제).
가로 스크롤바가 보이는 영역 안으로 들어오는 효과도 같이 얻었다(critic M-4).
미매칭 목록은 바깥 스크롤을 잃었으므로 자체 `max-height`를 갖게 했다.

테스트는 **어느 요소가 실제로 세로 스크롤되는지**까지 단언한다 — 그래야 같은 실수를 다시 잡는다.

### 🟠 fail-open — 화면은 "저장할 것 없음", 버튼은 "4셀 저장"

`window.PreviewTable?.buildTable(...)`가 `undefined`면 표가 안 그려져
`"저장될 항목이 없습니다."`가 뜨는데, `saveBtn.disabled`는 `willApplyCount`로만 정해져
**버튼은 활성 상태로 남았다.** 미리보기 없이 데이터가 저장되는 상태다.

조치: 옵셔널 체이닝을 걷어내고 **먼저, 크게 실패**시킨다(목록에 사유 표시 + 버튼 비활성).

### 🟠 중복 시료번호 — 배지와 표가 다른 수를 말한다

`1,5.1` · `2,6.2` · `1,7.7` 입력 시 배지는 "6셀 저장 예정", 표는 4칸. 합쳐서 사라진 값이
화면 어디에도 없다. 옛 목록은 6줄을 다 보여줘 중복이 눈에 띄었다 — **탐지 가능성의 회귀**다.

조치: `buildTable`이 `overwritten`을 보고하고, **항상 보이는 요약줄**에
`⚠️ 시료번호 중복 N건 (뒤 행이 앞 행을 덮어씀)`을 띄운다. 절단 안내도 같은 자리로 옮겼다
(목록 아래에 두면 260px 상자 밖이라 영원히 안 보인다).

### 🟠 미리보기 값 ≠ 저장 값 (codex)

`_commit`은 `if (!m.willApply) continue;` 뒤에 `apply()`하므로 최종값은
**willApply인 것 중 마지막**이지 그냥 마지막이 아니다. 충돌 정책이 `skip`/`fillBlank`면
뒤엣것이 `willApply=false`가 되어, 화면은 `6.9`(취소선)인데 저장은 `5.3`이 된다.

조치: 그룹핑이 `_commit`과 같은 규칙을 쓰도록 고치고 단위 테스트로 고정했다.
code-reviewer가 `_commit` 로직을 재현해 **oldValue 3종 × 정책 4종 × 값 4종, 중복 3개 기준
768조합 전수 대조 → 불일치 0건**을 확인했다.
