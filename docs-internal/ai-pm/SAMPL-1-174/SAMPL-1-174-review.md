# SAMPL-1-174 코드 리뷰 — 전체 보기 토글에 열이 함께 줄어들던 것

## 요청

> "전체 보기와 일반보기를 할때 컬럼의 크기가 변하고 있어 확인해줘"

## 원인

`.data-table`이 `width: 100%`라 **표가 화면보다 좁으면** 남는 폭을 모든 열이 나눠 갖는다.
그 상태에서 전체 보기로 열 둘(우편번호·경지구분)이 끼어들면 나머지가 전부 양보한다.

실측:

| 화면 폭 | 표 vs 화면 | 폭이 바뀐 열 | 최대 |
| --- | --- | --- | --- |
| 1280px | 표가 넓다 | **0개** | — |
| 1800px | 표가 좁다 | **12개** | −20.6px (전화번호) |
| 2560px | 표가 좁다 | **12개** | −34.1px |

## 수정

```css
.data-table td.col-lot-address { width: 100% }
```

표 레이아웃에서 `width: 100%`는 "이 열을 화면 폭만큼"이 아니라 **"남는 폭을 이 열에 몰아라"**로
동작한다. 다른 열이 내용 폭을 먼저 가져간 뒤 남은 것을 이 열이 받는다.
적용 후 폭이 바뀌는 열은 **1개**(흡수 열 자신)다.

`src/soil/index.html`의 `주소`·`필지 주소` th에 시맨틱 클래스를 붙였다 — 폭 동작과 무관하고,
열을 클래스로 가리키는 관례(SAMPL-1-131)를 맞춘 것이다.

선례: 자매 저장소 `sample-log-soil`의 **SLS-1-279**가 같은 증상을 같은 방식으로 해결(14개 → 1개).

규칙을 런타임에 무력화(`width:auto !important`)해 독립 재현한 수치가 위 표와 자릿수까지 일치했다.

중점 검토 답변:

1. **`td`만 준 선택이 옳다.** `th`가 필요해지는 유일한 경우는 tbody가 비어 머리글이 폭을 혼자
   정할 때인데, 0건이면 `renderLogs`가 표를 통째로 감추고 `#emptyState`를 띄운다 — **도달 불가**.
   실측: 빈 목록 토글 시 변동 0개.
2. **공용 규칙이 새지 않는다.** `col-lot-address`를 내보내는 곳은 `soil-script.js:3960` 한 곳뿐.
   다른 4개 시료 타입은 `col-address`만 쓰고, 흙토람은 `.heuktoram-table`이라 선택자에 걸리지 않는다.
3. **경계 7종 전부 흡수열 제외 0건** — 좁은 화면·초광폭·긴 주소·빈 값·공익직불제·전체 경지구분 탭.
   긴 주소는 `white-space: nowrap`이 min-content를 지배해 `width:100%`가 개입할 여지가 없다.
   인쇄·다크 모드는 폭과 직교한다.
4. **SAMPL-1-173 / sticky 오프셋에 영향 없음.** sticky 열이 전부 흡수 열 **왼쪽**이라 누적
   오프셋에 들어가지 않는다. 토글 전후 공통 sticky 열의 `left`가 소수점까지 동일했다.
5. **새 시험이 규칙을 붙잡는다** — 변이 검증을 리뷰어가 독립 재현했다.

지적 반영:

- **MINOR** CSS 주석이 같은 커밋의 HTML 변경과 모순("th에 클래스가 없다"고 적었는데 이 커밋이
  붙였다). 결론은 맞지만 근거가 틀렸다 → 진짜 이유(빈 목록에서 표가 감춰져 머리글만 남는 상태가
  없다)로 정정.
- **SUGGESTION** 1800px는 전체 보기 쪽 여유가 76px뿐인데 경지구분 열이 정확히 76.5px다 —
  그만한 열이 하나 더 늘면 시험이 **실패가 아니라 조용히 통과**한다 → 2560px로(여유 836px).

  통째로 사라진다 → `.then(() => undefined)`.
- **SUGGESTION** 폭 안정 판정을 연속 2회 → **3회**.
- **SUGGESTION** 열 이름 충돌 시 한 열이 조용히 검사에서 빠진다 → 키 개수 단정 추가.
