## 결함 — 실제 브라우저로 재현

`escapeHTML`한 값을 `textContent`·`dataset`에 넣어 **이중 이스케이프**가 됐다.
`textContent`는 HTML을 해석하지 않으므로 이스케이프가 불필요하고, 넣으면 코드가 글자로 보인다.

| 실제 입력 | 화면 표시(수정 전) |
| --- | --- |
| `김&철수` | `김&amp;철수` |
| `<특수> 시료` | `&lt;특수&gt; 시료` |

**수정 전 실측** (jsdom이 아니라 실제 렌더):

| 타입 | 셀 | 툴팁 |
| --- | --- | --- |
| 수질 | 6 | 3 |
| 잔류농약 | 5 | 2 |
| 중금속 | 4 | 1 |
| 퇴비 | 3 | 1 |
| **토양** | **0** | **0** |

### 🚨 토양이 0건인 이유를 내가 틀리게 적었다 (적대적 검증 MAJOR)

처음에 "템플릿 문자열로 그려 이스케이프가 올바른 자리에 있다"고 적었는데 **거짓이다.**
토양도 `createElement` + `textContent` + **원본 값**을 쓴다
(`soil-script.js:3397`·`:3416`·`:3456`·`:3483`; `innerHTML`은 비우기뿐).
즉 **이미 이 수정이 하는 것을 하고 있어서** 0건이었다.

그 거짓 설명은 **위험한 방향으로** 틀렸다 — "토양엔 이스케이프가 있다"고 읽히지만
실제로는 목록 경로에 이스케이프가 **아예 없다.** 누군가 `innerHTML` 셀을 추가하면
방어가 없다. 결함의 부재를 **확인이 아니라 추측한 아키텍처로** 설명한 것이 원인이다.
테스트 주석을 정정했다.

## 무엇을 바꿨나

4개 타입에서 `const safeXxx = escapeHTML(v)` → `const xxxText = v`.

**변수명도 바꿨다.** `safe`라는 이름이 붙은 채 이스케이프가 없으면 다음 사람이 그것을
템플릿 문자열에 그대로 써서 XSS를 만든다 — 이 세션에서 이름이 오해를 부른 사례를
이미 겪었다(`escapeHtml` vs `escapeHTML`이 대소문자만 다르고 의미가 반대였다).

각 선언부에 **왜 이스케이프하지 않는지**와 **템플릿에 쓸 때는 반드시 이스케이프하라**는
경고를 남겼다.

## XSS를 만들지 않았음을 어떻게 확인했나

이스케이프를 벗기는 변경이라 이것이 최우선이었다.

1. 변경된 변수의 **모든 사용처가 DOM API**임을 확인 — `textContent`·`dataset`·
   `setAttribute`·`el.title`. `innerHTML`·템플릿·`insertAdjacentHTML` 경로 **0건**
2. 독립 모델(codex)이 같은 결론을 냈다 — "`el.title` 대입도 DOM 프로퍼티라 안전"
3. 테스트에 **실제 XSS 페이로드**를 넣었다(codex MINOR 반영):
   `<img src=x onerror=alert(1)><script>alert(2)</script>` → 요소 생성 0건
4. 값이 **온전히 살아 있는지**도 함께 단언 — 막느라 데이터를 깎으면 안 된다

## 리뷰가 찾은 것 — 표시를 고치면서 새 표시 버그를 냈다

`escapeHTML(undefined)`는 `''`를 반환했으므로 폴백이 없어도 감춰져 있었다.
이스케이프를 벗기니 **`"undefined" 클릭하면...`** 툴팁이 생겼다(잔류농약).

그리고 **새 테스트가 토양의 같은 선재 결함을 발견**했다 — 토양은 이 티켓에서
건드리지 않았는데도 `row.name`을 폴백 없이 툴팁 템플릿에 넣고 있었다. 함께 고쳤다.

| 항목 | 조치 |
| --- | --- |
| 잔류농약 `nameText` 폴백 누락 | `\|\| '-'` 복원 |
| **토양의 같은 선재 결함** | 함께 수정(이 티켓이 만든 것이 아님을 주석에 명시) |
| 다이얼로그를 삼켜 XSS 신호를 버림 | 수집해 단언 — `injected`와 독립된 두 번째 방어선 |
| 툴팁 테스트에 비어있지 않음 가드 없음 | 추가 |
| 들여쓰기 불일치, `.gitignore` 누락 | 정리 |
