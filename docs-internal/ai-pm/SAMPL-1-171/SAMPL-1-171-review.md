# SAMPL-1-171 코드 리뷰 — 목록 가로 스크롤 시 고정 열 겹침

🔴 CRITICAL: 0건 / 🟠 MAJOR: 0건 / 🟡 MINOR: 1건 (수정) / 🔵 SUGGESTION: 0건
→ 판정: APPROVED

## 무엇이 문제였나

담당자 보고: "목록에서 가로로 스크롤하면 화면이 밀린다."

고정 열의 `left`가 페이지별 CSS에 **픽셀로 박혀** 있는데, 폭은 대부분 `min-width`라
내용에 따라 늘어난다. 그래서 각 고정 열이 자기 자리보다 왼쪽에 주차해 앞 열 위로 올라탄다.

### 실측 (1280px, 토양 목록)

| 열 | CSS `left` | 실제 자리 | 어긋남 |
| --- | --- | --- | --- |
| `col-num` | 85 | 90 | +5 |
| `col-date` | 150 | 164 | +14 |
| `col-category` | 240 | 268 | +28 |
| `col-landclass1` | 365 | 407 | +42 |
| `col-name` | 435 | 483 | **+48** |

끝까지 스크롤하면 `완료→접수번호` 4px, `접수일자→구분` 14px가 실제로 겹쳤다.
페이지 자체는 넘치지 않는다(`document.scrollWidth == clientWidth`) — 표 안에서 열이 겹치는 것이다.

**5개 시료 타입 전부** 같은 구조였다. `col-order`(차수)는 `sticky-col`을 달고도
`left` 규칙이 아예 없어(실측 `auto`) 공익직불제 모드에서는 고정되지도 않았다.

## 고치면서 세 번 틀렸다

1. **폭을 더해 구했다** → `border-collapse: separate`에서 rect 폭과 실제 이동량이 미세하게
   어긋나 1~3px 겹침이 남았다. → 고정을 **잠깐 풀고** 실제 자리를 읽는다.
2. **`ResizeObserver`로 헤더 셀을 관찰했다** → `display: table-cell`은 관찰 대상으로
   신뢰할 수 없다. 열 폭을 220px로 강제해도 콜백이 오지 않았다(실측).
   → 관찰 대신 폭이 멈출 때까지 **몇 초 따라간다**.
3. **`requestAnimationFrame`으로 따라갔다** → 부하가 걸리면 굶어서, 아직 변할 것이 남았는데
   "조용하다"고 판단해 그만뒀다(단독 실행 통과, 5개 병렬 실패). → **타이머**로 바꿨다.

폭은 렌더 뒤에도 계속 변한다 — 웹 폰트가 단계적으로 로드된다(실측: 32 → 35.8 → 39.1 → 40).
한 번 재고 마는 구현은 어긋난 채 남는다.

### `!important`를 쓴 이유

명시도로 이기려다 실패했다. `.data-table.gongik-on .col-order`(0,3,0)가 스코프
선택자(0,2,1)를 이겨 **공익직불제 모드에서만 하드코딩 값이 되살아났다**(실측 `left: 150px`,
14px 겹침). 선택자를 더 길게 쓰는 것은 명시도 겨루기일 뿐이라, "계산값이 항상 이긴다"를
규칙으로 못박았다.

### 스크롤 중에는 다시 재지 않는다

한때 scroll 이벤트에서 동기로 다시 쟀다. 정밀 측정이 강제 레이아웃을 두 번 일으켜
**스크롤이 버벅일** 위험이 있는데, 담당자가 호소한 것이 바로 스크롤 중 이상이라
그 대가는 치를 수 없다. 대신 미리 맞춰 둔다.

## 독립 리뷰(codex)

🟡 `measureNaturalOffsets`가 클래스를 붙였다 떼는데 `finally`가 없어, 예외 시 고정이
풀린 채 남을 수 있다 → `try/finally`로 감쌌다. 그 상태는 원래 결함보다 나쁘다.

나머지(정착 루프의 종료 조건, `!important` 타당성, 중간 상태 노출, `renderLogs` 훅 위치,
성능·메모리)는 문제 없음으로 확인됐다.

## 변이 검증

| 변이 | 결과 |
| --- | --- |
| A. 계산 무력화 | **11건 전부 실패** |
| B. `!important` 제거 | 공익직불제 시험 실패 |
| C. 정밀 측정 → 폭 합산 | **검출되지 않음** |

⚠️ **C를 정직하게 남긴다.** 폭 합산으로 되돌려도 11건이 그대로 통과한다 — 남는 오차가
1px이라 "겹치지 않는다" 기준을 지나간다. 0.5px 정확도를 단정하는 시험도 만들어 봤으나
폰트가 정착하는 동안 서브픽셀이 계속 흔들려 실행마다 결과가 달라져 **제거했다**
(흔들리는 시험은 두지 않는다). 정밀 측정을 남긴 이유는 `border-collapse`·`border-spacing`·
표 안쪽 여백을 일일이 더하지 않아도 **구성상 옳기** 때문이다.
독립 리뷰도 "테스트 민감도의 한계이지 구현의 결함은 아니다"로 판정했다.
다만 **"0.5px 정확하다"는 주장은 시험으로 입증되지 않았다**는 점을 명시해 둔다.
