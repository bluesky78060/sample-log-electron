# SAMPL-1-170 코드 리뷰 — 공통 엑셀 가져오기의 접수번호 중복 검사

🔴 CRITICAL: 0건 / 🟠 MAJOR: 4건 (전부 수정) / 🟡 MINOR: 2건 (수정) / 🔵 SUGGESTION: 0건
→ 판정: APPROVED (독립 리뷰 4라운드)

## 무엇이 없었나

`ExcelImportManager`(5개 타입이 공유)에 **접수번호 중복 검사가 아예 없었다.**

```js
const hasReceptionNumbers = this._parsedLogs.some(l => l.receptionNumber !== '');
if (hasReceptionNumbers) return;    // 시트에 번호가 있으면 검사 없이 그대로 저장
```

`maxNum + 1`은 로컬만 보므로 클라우드에 더 큰 번호가 있으면 그대로 충돌했다.

## 무엇을 했나

- `fetchCloudReceptionRecords`를 `soil-script.js` → `BaseSampleManager`로 **이동**
  (완전히 범용이었다 — `this.moduleKey`만 쓴다). 5개 타입이 함께 쓴다.
- 로컬 + 클라우드로 번호 풀을 만들어 **시트 번호 · 배치 내 중복**을 판정한다.
- 자동부여가 풀을 **건너뛰며** 올린다.
- 중복이면 **저장을 막는다.** 이 매니저에는 토양 같은 "건너뛰기/덮어쓰기" 선택이
  없어, 통과시키면 담당자가 모른 채 중복이 들어간다.
- 클라우드 확인 실패는 막지 않되 **미리보기에 적는다** (오프라인 우선).

## 독립 리뷰가 잡은 것

| # | 지적 | 실체 |
| --- | --- | --- |
| 1 | 🟠 이전 세션 상태 승계 | `_cloudChecked`가 true로 남아, 연도를 바꾸고 새 파일을 연 뒤 조회 전에 눌러도 통과했다 |
| 2 | 🟠 부분 번호 시트 | 한 행이라도 번호가 있으면 곧바로 돌아가, **빈 행이 접수번호 없이 저장**됐다 |
| 3 | 🟠 복합 접수번호 | 수질은 그룹 접수를 `"100, 101"`로 저장한다(`water-script.js:401`). 통째로 비교해 `101`을 놓쳤고 `parseInt('100, 101')`은 100이라 최대값도 틀렸다 |
| 4 | 🟠 **토양도 공통 매니저를 쓴다** | "토양은 자체 importer만 쓴다"고 넘겼는데 틀렸다. `manager`를 안 넘겨 토양 엑셀 가져오기만 클라우드를 못 봤다 |
| 5 | 🟡 SafeInteger 경계 | 그냥 빠져나가면 **이미 쓰인 번호를 그대로 부여**했다 |
| 6 | 🟡 `no-db` 오판 | `getAllWithMeta`만 있는 구현을 "DB 없음"으로 처리했다 |

3번과 4번은 **내가 사실 확인 없이 좁게 가정한 것**이다. 수질의 쉼표 저장도,
토양이 공통 매니저를 함께 쓴다는 것도 코드를 보면 바로 나온다.
