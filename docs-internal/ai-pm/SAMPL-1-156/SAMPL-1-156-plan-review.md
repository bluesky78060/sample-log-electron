# SAMPL-1-156 플랜 리뷰

## ⚠️ 플랜 리뷰를 수행하지 않았다 (정직한 기록)

`critic` 플랜 리뷰를 **실행하지 않았다.** 사유: 사용자 지시("코드 수정이나 중요가 낮은 작업은 플랜리뷰하지말고 진행").

## 생략을 정당화하는 근거
- 검증된 원본이 있다 — soil `c8cf319`(유닛 647 / E2E 246 / 변이 11종 검출, codex 계획+코드 리뷰 반영)
- 조회 전용 기능이고 기존 데이터·채번을 건드리지 않는다
- 메인에 마크업이 이미 있어 구조를 새로 정하지 않는다

## 그래도 남는 리스크와 대응
1. **배선 예외가 접수 등록을 죽이는 것** — 원본이 실제로 밟은 함정. 배선 전체를 try/catch로 감싸고 변이로 실증한다.
2. **메인과 soil의 배선 순서·셀렉터 차이** — 원본을 그대로 붙이면 조용히 안 걸릴 수 있다. 0단계에서 먼저 실측한다.
3. **테스트가 잘못된 이유로 통과** — SLS-1-223에서 필수 필드를 안 채워 HTML5 검증에 막힌 걸 "가드가 막았다"고 오해했다. 등록 관련 단정에는 필수 필드를 전부 채우고, 차단 사유(토스트 문구)에 결합한다.
4. **런타임 데이터 교체** — 로더가 `CROP_DATA`·`CROP_CATEGORIES`를 갈아끼우므로 캡처 금지. 분류 옵션은 열 때마다 재생성.

## 코드 리뷰와 적대적 검증은 생략하지 않는다
이 세션에서 코드 리뷰 APPROVED 뒤 적대적 검증이 결함을 찾은 사례가 두 번 있었다(SAMPL-1-153, SLS-1-222). 같은 순서로 진행한다.
