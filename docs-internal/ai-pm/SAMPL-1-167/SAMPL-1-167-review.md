# SAMPL-1-167 코드 리뷰 — 등록 직전 클라우드 접수번호 확인 (A안)

## 담당자가 A안을 선택했다

SAMPL-1-166에서 세 선택지를 제시하고 받은 답이다. **두 자리에서 접수**한다는 것이
확인됐고, B안(병합 시점 탐지)은 사후 발견일 뿐이라 근본 차단이 필요했다.

## 설계 — 확인할 수 있을 때 강해지고, 못 할 때 막지 않는다

A안의 알려진 대가는 "오프라인에서 등록이 막히거나 느려진다"이다. 이 앱은
**오프라인 우선**이라(`CLAUDE.md`) 막히게 두면 현장에서 못 쓴다.

| 상황 | 동작 |
| --- | --- |
| Firebase 켜짐 + 응답 | 클라우드 번호를 검사 풀에 합쳐 **차단·재부여** |
| Firebase 꺼짐 | 종전대로 로컬만 (조용히) — 확인할 것이 없다 |
| 실패·시간초과 | **등록은 되고**, "확인하지 못했다"고 알린다 |

## 독립 리뷰 레인

- **gemini: 미수행** — `GOOGLE_CLOUD_PROJECT` 미설정. **실행하지 않은 검증을 통과로 적지 않는다.**
- **codex: 수행** — CRITICAL 0 / **MAJOR 3** / MINOR 2

### MAJOR — 이 수정이 **없애려던 중복을 스스로 만들 뻔했다**

`submitForm`이 클라우드 확인 때문에 async가 됐다. 그 사이(최대 4초)에 담당자가
버튼을 다시 누르면 **같은 번호로 여러 건이 등록된다.**

변이 검증으로 실증했다 — 가드를 빼자 `홍길동:400`이 **세 번** 저장됐다.

→ `_submitting` 플래그로 이중 제출을 막고 `finally`로 해제한다.

### MAJOR — 실패 경로가 **죽은 코드**였다

`loadFromFirebase`는 오류를 **내부에서 삼키고** `{ data: [] }`를 돌려준다
(`BaseSampleManager.js:583`). 그래서:

- 내 `catch`는 **절대 실행되지 않는다**
- 네트워크 오류가 **"클라우드에 0건"으로 보여** 중복 검사가 조용히 통과한다
- "확인하지 못했다"는 알림도 뜨지 않는다

**이 티켓이 막으려는 바로 그 실패를, 이 티켓의 코드가 저지르고 있었다.**

→ `firestoreDb`를 **직접** 부른다. 읽기 성공 여부를 알아야 하기 때문이다.
E2E 스텁도 `loadFromFirebase`가 아니라 `firestoreDb`를 겨냥하도록 바꿨다 —
전자를 스텁하면 "실패를 실패로 아는지"를 검증할 수 없다.

### MAJOR — 그룹 수정 경로 (별 티켓으로 분리)

리뷰는 "클라우드 확인을 우회한다"고 지적했는데, 확인해 보니 **그보다 크다** —
`editingGroupIds` 분기에는 **로컬 중복 검사조차 없다**(`grep -c duplicateNumbers` → 3,
전부 신규 등록 분기).

그룹 수정은 **자기 번호를 그대로 쓰는 것이 정상**이라 신규 등록의 검사를 그대로
붙이면 정상 수정이 막힌다. 자기 제외 설계가 필요해 서둘러 끼워 넣지 않고
**SAMPL-1-168**로 분리했다.

### MINOR 대응

| 지적 | 대응 |
| --- | --- |
| 임시 `sampleLogs` 교체가 예외 시 복구되지 않는다 | `try/finally`로 감쌌다. 안 그러면 목록·저장·내보내기가 클라우드 사본을 로컬 데이터로 취급한다 |
| `Promise.race` 타이머가 정리되지 않는다 | 타이머를 잡아 `finally`에서 `clearTimeout`. 원래 요청 취소는 Firestore SDK가 지원하지 않아 남는다 |
| 4초의 근거가 코드에 없다 | `SOIL_CLOUD_PRECHECK_TIMEOUT_MS` 상수로 빼고 **"현장 실측이 아니라 잠정치"**임을 주석에 명시 |

리뷰가 **정상이라고 확인한 것**: 로컬+클라우드 단순 결합이 중복 판정·재채번 목적에
맞다는 점, 화면에 클라우드 사본을 넣지 않은 점, 경지구분 필터가 적용돼 다른
경지구분의 같은 번호를 오탐하지 않는 점.

## 남은 한계

- **그룹 수정·단일 수정 경로는 여전히 무방비다** → SAMPL-1-168.
- **4초 상한은 잠정치다.** 느린 회선에서 정상 응답이 실패로 처리되면 경고가 잦아진다.
  담당자 환경에서 관찰되면 이 값부터 조정한다.
- **시간초과 후에도 원래 Firestore 요청은 계속 진행된다.** SDK가 취소를 지원하지 않는다.

  그때는 SAMPL-1-166의 병합 탐지가 사후에 잡는다. 두 겹이 함께 있어야 의미가 있다.
- 토양만이다. 다른 4개 시료 타입의 채번 경로는 별건이다.
