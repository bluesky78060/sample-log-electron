이식 성격

두 프로젝트가 분기됨 — soil은 구버전 Base, 메인은 L1 리팩토링. "개념을 메인 구조에 재배선".

데이터 마이그레이션

스크립트 불필요

읽기 시 || '농가의뢰' 폴백 + 로드 1회 채움. 스토리지 구조 변경 없음, 하위호환 안전.

⚠️ 먼저 결정해야 할 사항 (구현 전 확정 필요)

🟣 결정 1 — 흙토람 "경지구분 1차" 의미 충돌 (가장 중요) soil 흙토람에서 "경지구분 1차" 컬럼 = landClass1(개량제/직불/…)을 출력합니다(heuktoram-script.js:1600). 그런데 메인 흙토람은 같은 "경지구분 1차" 컬럼을 이미 subCategory(논/밭/과수)에서 파생해 채우고 있습니다 — 같은 칸의 의미가 다릅니다.

선택지: A. soil과 동일하게 landClass1을 1차 컬럼에 출력(메인 기존 매핑 교체) B. 메인 기존 매핑 유지하고 landClass1은 별도 칸/미반영 C. 흙토람 연동은 이번 범위 제외(폼·목록·채번만)
→ 이 결정이 Phase 6 포함 여부를 좌우합니다.
🟣 결정 2 — 엑셀 가져오기 범위 soil은 전용 soil-result-importer.js(67KB, 경지구분 일괄선택 + 경지구분별 채번)를 씁니다. 메인은 공유 ExcelImportManager 기반이라 그대로 못 옮깁니다. 메인 importer에 "경지구분 일괄선택 UI + 경지구분별 채번"을 새로 붙여야 합니다.
→ 포함(Phase 5 진행) 제외(수기 입력만, 후속)
🟣 결정 3 — 채번 순수모듈 도입 여부 soil은 reception-number.js 순수모듈로 분리. 메인은 인라인 generateNextReceptionNumber()(인자 없음). A. soil처럼 모듈 신규 도입(테스트 용이, soil-entry 수정) B. 메인 인라인에 landClass1 필터만 추가(변경 최소) → 권장: B(변경 최소) + 채번 핵심 로직만 단위테스트 가능하게 작은 순수함수로 추출.

🧩 핵심 동작 — 경지구분별 독립 접수번호

soil의 채번 순수 로직(reception-number.js, 58줄)을 메인에 맞게 적용:

// 같은 landClass1 범위 내에서만 본번 max+1
function computeNextNumber(logs, targetClass, opts = {}) {
    const def = '농가의뢰';
    const fillPrefix = opts.fill ? 'F' : '';
    const max = logs
        .filter(l => (l.landClass1 || def) === targetClass)          // ← 경지구분별 필터
        .map(l => parseInt(String(l.receptionNumber).replace(/^F/, '').split('-')[0], 10) || 0)
        .reduce((a, b) => Math.max(a, b), 0);
    return fillPrefix + (max + 1);
}
폼: 경지구분 select 변경→ change 핸들러 (수정모드 아니면)→ computeNextNumber(logs, 선택분류)→ 접수번호 입력칸 자동 갱신

메인은 채번이 BaseSampleManager가 아닌 soil-script 자체 메서드라 L1과 직접 충돌 없음. 호출처(접수번호 자동입력 지점)만 점검하면 됩니다.
