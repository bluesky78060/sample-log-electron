## 2. 문제별 상세 분석 및 수정

### 2.1 삭제 버튼 미작동

**증상**: 목록 뷰에서 관리 컬럼의 "삭제" 버튼을 클릭하면 confirm 다이얼로그는 나타나지만 실제 삭제가 되지 않음. "선택 삭제"(일괄)는 정상 작동.

**근본 원인 2가지**:

#### 원인 A: saveLogs()의 await batchSave 블로킹

```
삭제 버튼 클릭
  → deleteSample(id) 또는 deleteGroup(groupId) 호출
  → this.sampleLogs.filter(...)로 메모리에서 제거
  → await this.saveLogs()  ← 여기서 블로킹!
    → await firestoreDb.batchSave(전체 레코드)
      → Firebase Quota exceeded → 무한 재시도 (backoff)
      → Promise가 절대 resolve되지 않음
  → this.filterAndRenderLogs()  ← 실행되지 않음 (UI 갱신 안 됨)
```

`saveLogs()`가 Firebase `batchSave`를 `await`하는데, Quota 초과 상태에서 Firebase SDK가 무한 재시도(exponential backoff)하여 Promise가 resolve되지 않음. 따라서 `filterAndRenderLogs()`가 실행되지 않아 UI가 갱신되지 않음.

#### 원인 B: pesticide-script.js strict 비교

```javascript
// 버그 코드 (pesticide-script.js line 2315)
this.sampleLogs = this.sampleLogs.filter(item => item.id !== id);
// item.id: number (구 데이터) 또는 string (UUID)
// id: string (항상, dataset.id에서 가져옴)
// 1 !== "1" → true → 필터링 안 됨 (삭제 실패)
```

**수정 파일 및 내용**:

| 파일 | 수정 내용 |
|------|----------|
| `src/soil/soil-script.js` | `deleteSample()`: `log.id !== id` → `String(log.id) !== String(id)` |
| `src/soil/soil-script.js` | `deleteGroup()`: `deleteIds.includes(this.editingLogId)` → `deleteIds.map(String).includes(String(this.editingLogId))` |
| `src/pesticide/pesticide-script.js` | line 2315: `item.id !== id` → `String(item.id) !== String(id)` |

### 2.2 Firebase Quota 초과 (핵심 수정)

**증상**: Firebase 콘솔에 `Quota exceeded` 에러. 데이터 100건 기준 2회 저장만으로 200 writes 소진. 일일 20,000 writes 무료 한도가 빠르게 소진됨.

**근본 원인**: `saveLogs()`가 호출될 때마다 **전체 레코드**를 `batchSave`

```
Before (문제):
  1건 추가 → saveLogs() → batchSave(100건) = 100 writes
  1건 수정 → saveLogs() → batchSave(100건) = 100 writes
  1건 삭제 → saveLogs() → batchSave(99건) = 99 writes

  접수 1건 = 최소 200~300 writes 소진
```

**수정 전략**: localStorage 우선 저장 + Firebase는 변경분만 개별 저장

```
After (수정 후):
  1건 추가 → saveLogs(localStorage) + firebaseSaveRecords(1건) = 1 write
  1건 수정 → saveLogs(localStorage) + firebaseSaveRecords(1건) = 1 write
  1건 삭제 → saveLogs(localStorage) + firebaseDeleteRecords(1건) = 1 write

  접수 1건 = 1~3 writes 소진 (99% 절감)
```

**수정 파일 및 내용**:

#### BaseSampleManager.js (공통 — water, compost, heavy-metal, pesticide 영향)

```javascript
// Before: saveLogs()
async saveLogs() {
    // ...
    if (window.firebaseConfig?.isEnabled()) {
        await window.firestoreDb.batchSave(this.moduleKey, year, this.sampleLogs); // 전체!
        localStorage.setItem(key, serialized);
    }
}

// After: saveLogs()
async saveLogs() {
    // ...
    localStorage.setItem(key, serialized); // 로컬만 저장
    // Firebase는 호출자에서 개별 처리
}
```

```javascript
// Before: deleteSample()
async deleteSample(id) {
    await window.firestoreDb.delete(..., id); // await 블로킹!
    this.sampleLogs = this.sampleLogs.filter(...);
    localStorage.setItem(...);
}

// After: deleteSample()
async deleteSample(id) {
    this.sampleLogs = this.sampleLogs.filter(...); // 로컬 먼저
    await this.saveLogs();
    this.filterAndRenderLogs();
    // Firebase는 백그라운드 (fire-and-forget)
    window.firestoreDb.delete(..., id).catch(...);
}
```

#### soil-script.js (토양 전용 — soil은 deleteSample/deleteGroup을 override)

새로 추가된 헬퍼 메서드:

```javascript
// Firebase 개별 저장 (변경분만)
firebaseSaveRecords(logs) {
    const promises = arr.filter(log => log.id)
        .map(log => firestoreDb.save('soil', year, String(log.id), log));
    Promise.allSettled(promises).then(results => {
        const failed = results.filter(r => r.status === 'rejected');
        if (failed.length > 0) showToast(`클라우드 동기화 ${failed.length}건 실패`, 'warning');
    });
}

// Firebase 개별 삭제
firebaseDeleteRecords(ids) {
    const promises = arr.map(id => firestoreDb.delete('soil', year, String(id)));
    Promise.allSettled(promises).then(...);
}

// 전체 동기화 (JSON import / 엑셀 import 전용)
firebaseBatchSync() {
    const snapshot = [...this.sampleLogs]; // 스냅샷 캡처
    firestoreDb.batchSave('soil', year, snapshot).catch(...);
}
```

각 호출 지점 수정:

| 동작 | saveLogs() 후 추가 호출 |
|------|----------------------|
| 새 등록 (접수) | `this.firebaseSaveRecords(newLogs)` |
| 수정 (편집) | `this.firebaseSaveRecords(updatedLog)` |
| 그룹 수정 | `this.firebaseDeleteRecords(removedIds)` + `this.firebaseSaveRecords(newLogs)` |
| 개별 삭제 | `this.firebaseDeleteRecords(id)` |
| 그룹 삭제 | `this.firebaseDeleteRecords(deleteIds)` |
| 선택 삭제 (일괄) | `this.firebaseDeleteRecords(selectedIds)` |
| 완료 처리 | `this.firebaseSaveRecords(changedLogs)` |
| 일괄 완료 | `this.firebaseSaveRecords(changedLogs)` |
| 발송일자 입력 | `this.firebaseSaveRecords(changedLogs)` |
| JSON 불러오기 | `this.firebaseBatchSync()` (전체 동기화) |
| 엑셀 가져오기 | `this.firebaseBatchSync()` (전체 동기화) |

### 2.3 필지 주소 검증(addressVerified) 새로고침 시 유실

**증상**: VWORLD API로 필지 주소 검증 후 빨간색 표시가 정상 작동하지만, 새로고침하면 검은색(기본)으로 돌아감.

**근본 원인**:

```
validateAndMarkLogs() 완료
  → log.addressVerified = false 설정
  → localStorage에 저장 ✓
  → Firebase에는 저장 안 됨 ✗

새로고침 시:
  → loadYearData() 실행
  → Firebase에서 데이터 로드 (addressVerified 없음)
  → localStorage를 Firebase 데이터로 덮어씀
  → addressVerified 유실!
```

**수정**:

```javascript
// Before: validateAndMarkLogs()
if (changed) {
    localStorage.setItem(...); // localStorage만 저장
}

// After: validateAndMarkLogs()
if (changed) {
    localStorage.setItem(...);
    this.firebaseSaveRecords(verifiedLogs); // Firebase에도 저장
}
```

## 4. 테스트 프로젝트 반영 시 주의사항

### 반드시 복사할 파일

```
src/shared/BaseSampleManager.js  → 테스트 프로젝트에 복사
src/soil/soil-script.js          → 테스트 프로젝트에 복사 (STORAGE_KEY 복원 필요!)
src/pesticide/pesticide-script.js → 테스트 프로젝트에 복사 (STORAGE_KEY 복원 필요!)
```

### 복사 후 반드시 확인/수정할 사항

1. **STORAGE_KEY 접두사**: 테스트 프로젝트는 `test_` 접두사 사용
   ```javascript
   // 메인: const STORAGE_KEY = 'soilSampleLogs';
   // 테스트: const STORAGE_KEY = 'test_soilSampleLogs';
   ```

2. **COLLECTION_PREFIX**: Firestore 컬렉션명에 `test_` 접두사
   ```javascript
   // 테스트: COLLECTION_PREFIX = 'test_'
   ```

3. **암호화 코드 보존**: 테스트 프로젝트에만 존재하는 암호화 관련 코드를 덮어쓰지 않도록 주의
   - `encryptionManager.init()` 호출
   - 암호화 스크립트 태그
   - 상세: `sync-rule.md` 참조

4. **soil-script.js의 firebaseSaveRecords/DeleteRecords/BatchSync**:
   - soil만 override하므로 BaseSampleManager를 상속하는 다른 4개 타입은 이 헬퍼가 없음
   - 다른 4개 타입은 BaseSampleManager의 saveLogs(localStorage만) + 기존 inline Firebase delete로 동작
