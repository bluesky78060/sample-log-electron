## 2. 등록 완료 모달 주소 검증 (신규 기능)

### 2.1 UX 흐름

```
접수 등록
  → 등록 결과 모달 표시
  → 닫기/내보내기 버튼 비활성화
  → "필지 주소 검증 중..." 스피너 표시
  → 검증 중 모달 닫기 불가 (오버레이 클릭 차단)
  → VWORLD API 호출 (3~8초)
  → 검증 완료:
      ✅ 정상: "필지 주소 N건 검증 완료" (초록색)
      ❌ 불일치: "필지 주소 N건 불일치" + 주소 목록 (빨간색) + 수정 버튼
      ⚠️ 스킵: "주소 검증을 수행할 수 없습니다" (노란색)
  → 닫기/내보내기 버튼 활성화
  → 불일치 시 "수정" 버튼 클릭 → editSample() → 편집 모드 진입
```


**closeRegistrationResultModal()** — 검증 중 닫기 차단:
```javascript
closeRegistrationResultModal() {
    if (this._verificationInProgress) return; // 검증 중 닫기 방지
    // ...
}
```

**등록 흐름 변경** (폼 제출 핸들러):
```javascript
// Before:
this.validateAndMarkLogs(newLogs).catch(...); // 백그라운드 (fire-and-forget)
this.showRegistrationResult(resultData);

// After:
this.showRegistrationResult(resultData);

```

## 3. 하위필지(subLots) 주소 검증

### Before
```javascript
// parcels의 lotAddress만 검증
const addresses = log.parcels.map(p => p.lotAddress).filter(Boolean);
```

### After
```javascript
// parcels + subLots 모두 검증
const addresses = [];
log.parcels.forEach(p => {
    if (p.lotAddress) addresses.push(p.lotAddress);
    if (p.subLots) p.subLots.forEach(s => {
        const addr = typeof s === 'string' ? s : s.lotAddress;
        if (addr) addresses.push(addr);
    });
});
```

subLots는 `string` 또는 `{ lotAddress: string }` 형태로 저장되므로 둘 다 처리.

## 4. CI 빌드 VWORLD_API_KEY 주입

### 문제
- `.github/workflows/build.yml`에서 `network-config.example.js`를 복사
- example 파일에는 `VWORLD_API_KEY`가 없음
- CI로 빌드된 Windows exe에서 주소 검증 미작동

### 수정

```yaml
# Before:
- name: Create network-config from example
  run: copy src\shared\network-config.example.js src\shared\network-config.js

# After:
- name: Create network-config with secrets
  run: |
    @"
    window.NETWORK_CONFIG = {
        ALLOWED_GATEWAY: '${{ secrets.ALLOWED_GATEWAY }}',
        VWORLD_API_KEY: '${{ secrets.VWORLD_API_KEY }}'
    };
    "@ | Out-File -FilePath "src/shared/network-config.js" -Encoding utf8
```

### GitHub Secrets 등록

| Secret | 값 |
|--------|-----|
| `VWORLD_API_KEY` | `5390BC39-A15B-3BA2-8025-28867877615A` |
| `ALLOWED_GATEWAY` | `111.21.101.254` |

설정 위치: GitHub → Settings → Secrets and variables → Actions

## 5. 테스트 프로젝트 반영 시 주의사항

### 복사 대상 파일

| 파일 | 비고 |
|------|------|
| `src/soil/index.html` | 모달 HTML 변경 (addressVerifyStatus 영역 추가) |
| `src/soil/soil-script.js` | runVerificationForModal, subLots 검증 등 (**STORAGE_KEY 복원 필수!**) |
| `src/style.css` | 검증 UI 스타일 + 다크모드 |
| `.github/workflows/build.yml` | CI secrets 주입 방식 (테스트 프로젝트에 별도 repo secrets 필요) |

### 주의사항

1. **STORAGE_KEY**: 테스트 프로젝트는 `test_` 접두사 사용
2. **암호화 코드 보존**: `encryptionManager` 관련 코드 덮어쓰지 않기
3. **GitHub Secrets**: 테스트 프로젝트 repo에도 `VWORLD_API_KEY`, `ALLOWED_GATEWAY` secrets 등록 필요
4. **운영키 전환 시**: secrets 값만 업데이트하면 다음 빌드부터 반영됨
